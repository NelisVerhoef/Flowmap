## A "refactor" of router registration that unregisters the utils router: the health check and test-email endpoints are removed

**Lands on:** operate-deployment → *Docker Compose / CI probes the backend health endpoint* (`orchestrator-probes-health`), *Admin sends a test email to check SMTP settings* (`admin-sends-test-email`). Both are removed, not modified. Every other flow is now registered through the new loop, and its behaviour is unchanged.
**New on the map:** nothing. Two steps leave it: `GET /utils/health-check/` and `POST /utils/test-email/`. The loop in `backend/app/api/main.py:<module>` is off-map plumbing, not a step.

> Lens note: `flowmap lens main pr-24` crashes on the head (`AttributeError: 'Call' object has no attribute 'id'` in `adapters/fastapi.py:_mounts`), because the adapter can't read `include_router(import_module(...).router)`. I re-ran it with a scratchpad patch that expands the `ROUTERS` loop. Result: **2 endpoints removed** (the two above), 0 steps touched by anchors, 0 reach, reach diff 0 edges added and 0 removed, 1 off-map symbol, no tests changed. With a patch that only skips mounts it can't resolve, 22 endpoints show as removed (all of login/users/items/utils). So this registration style also hides every flow from the map's inventory.

### Before → after
- orchestrator-probes-health: `GET /api/v1/utils/health-check/` returned `true` → now returns **404**. The request falls through to the `app.frontend("/")` catch-all, and that only serves `index.html` when the request's Accept header names `text/html`. curl sends `*/*`.
- admin-sends-test-email: a superuser's `POST /api/v1/utils/test-email/` sent an SMTP test mail → now returns **404**.
- sign-in, sign-up, manage-items, manage-own-account, administer-users, recover-forgotten-password: unchanged. The same modules and the same `.router` objects are registered in the same relative order (login, users, items). The utils paths overlap with none of them, so removing utils doesn't change how any other route matches.

### Shape
- Intent vs size: the commit says "register routers from one list", which reads as a refactor with no behaviour change. The diff is +7/−5 in one file, but the behaviour change is larger than that intent: one of the four routers is missing from the list. The busiest part is the `import_module(f"app.api.routes.{name}")` loop, and that busyness is accidental. It swaps four checked imports for strings, which is what let the omission through: there is no unused-import lint and no NameError. It is also what broke flowmap's inventory.
- Blast radius (through infrastructure, not the call graph):
  - `compose.yml` health-checks the backend with `curl -f http://localhost:8000/api/v1/utils/health-check/`.
  - `.github/workflows/test-docker-compose.yml` runs `up -d --wait` and then curls the same path.
  - The generated client is not regenerated, so `UtilsService.healthCheck/testEmail` remains in `frontend/src/client/sdk.gen.ts`.
  - The backend container also serves the SPA (the Dockerfile copies the build in, and `app.frontend("/")` serves it).
  - The proxy is Traefik v3.7 with `--providers.docker`, which doesn't route to a container whose health is starting or unhealthy. The probe failing therefore takes the whole domain offline, not just the probe.
- Tests: none changed. There is no `backend/tests/api/routes/test_utils.py`, so pytest stays green. Both removed steps have map evidence `agreed`, not `tested`. Only the docker-compose workflow would catch this.
- Reversibility: nothing is persisted, so a revert is clean.

### Questions to ask
1. **Blast radius: operate-deployment → orchestrator-probes-health.** `ROUTERS = ("login", "users", "items")` leaves out `utils`. Did you mean to remove `GET /utils/health-check/`? `compose.yml` probes it with `curl -f`, so after a deploy the backend never becomes `healthy`. Traefik's docker provider skips a container that isn't healthy, and that one container serves both `/api/v1` and the frontend. As far as I can tell, every user gets a Traefik 404 on the whole domain. Is that wrong?
2. **User-visible: admin-sends-test-email.** The same omission removes `POST /utils/test-email/`. Any ops script, runbook or API client that checks SMTP this way now gets a 404. Was this a deliberate deprecation? If it was, where is the replacement and the regenerated client? `UtilsService` is still exported.
3. **Failure: CI.** Did `test-docker-compose.yml` run on this PR? `docker compose up -d --wait backend adminer` should fail because the healthcheck never passes. If it went green, what actually ran?
4. **Alternatives / altitude:** why strings plus `import_module` rather than `for module in (login, users, utils, items): api_router.include_router(module.router)`? The string form turns a missing or misspelled router into a silent omission. It also hides routes from static tools: flowmap's FastAPI adapter crashes on it, and once patched it sees no endpoints except `private`. "Find usages" in an IDE finds nothing too. What does the string list give you that a tuple of modules doesn't?
5. **Map gap: tests.** Neither utils step is `tested`. Will you add a test that pins the registered route set, for example `GET /api/v1/utils/health-check/` returns 200, so that the next registration refactor can't drop a router without a red test?

After: if the omission was deliberate, two steps leave operate-deployment, so re-run the map loop (`docs/flowmap/README.md`). If the dynamic registration stays, flowmap's FastAPI adapter needs to support it first. Otherwise the inventory loses every non-private endpoint.

VERDICT: do-not-merge
