# Review: pr-04 "api: simplify router registration"

**What it does:** It removes the `if settings.FASTAPI_ENV == "development"` guard in `backend/app/api/main.py`, so the test-only `private` router (`POST /api/v1/private/users/`) is now mounted in every environment, production included.

**What existing behaviour changes:**
- The commit message describes a refactor, but the change alters behaviour. Production does not set `FASTAPI_ENV`: `compose.deploy.yml` and the FastAPI Cloud `deploy.yml` job leave it unset, `.env` is excluded by `.fastapicloudignore` and is not copied into the Docker image, and only `compose.override.yml` and the test/codegen scripts set it. So today `/api/v1/private/users/` returns 404 in prod. After this merge it is a live, **unauthenticated** user-creation endpoint, and it shows up in the prod OpenAPI schema.
- The endpoint skips every check that `/users/signup` does. `email` is a plain `str` (not `EmailStr`), the password has no 8–128 length limit, `full_name` has no length limit, and there is no duplicate-email check, so a duplicate fails as an IntegrityError and returns a 500. `is_verified` is accepted and then silently dropped.
- **This breaks existing data and clients.** SQLModel table models do not validate, so an anonymous `POST {"email":"not-an-email",...}` commits a row. After that, `UserPublic.model_validate()` raises (I checked this against the PR's `models.py`). The create call itself returns 500 after the commit has already happened. The superuser `GET /api/v1/users/` (the admin page) also returns 500, because it lists newest-first and validates every row. One anonymous request takes the admin user list down until someone deletes the row by hand.
- CI won't catch this. `backend/scripts/test.sh` always runs with `FASTAPI_ENV=development`, and no test checks that the route is absent outside dev.

**Questions for the author (ranked):**
1. Did you intend to expose `/api/v1/private/users/` in production? It is an unauthenticated endpoint that writes users directly to the DB. If not, why does a "simplify" commit remove the only thing gating it?
2. How do you stop anonymous callers from storing invalid emails, weak or empty passwords and oversized names? As shown above, one bad email row makes `GET /api/v1/users/` return 500 for every admin.
3. If an always-on router is really needed, for example for E2E against a deployed env, why not protect it with auth or a separate opt-in flag that is off by default in prod, rather than removing the guard?
4. Which test proves the private router is *not* reachable when `FASTAPI_ENV` is unset? Every current test runs in development mode.
5. Should `is_verified` stay in `PrivateUserCreate` when nothing persists it?

VERDICT: do-not-merge
