# Review: pr-20 (items: extract the ownership check)

**What it does:** Moves the identical "load item → 404 if missing → 403 if not owner and not superuser" block from `read_item`, `update_item` and `delete_item` in `backend/app/api/routes/items.py` into one module-level helper, `get_owned_item(session, current_user, id)`, and calls it from all three.

**Existing behaviour that changes:** None that I can find. The helper's body is the removed code word for word: same `session.get`, same check order (404 before 403), same status codes, same `detail` strings, same superuser bypass. The routes call it as a plain function. It is not a `Depends`, so the `SessionDep`/`CurrentUser` annotations on its parameters do nothing and it uses the request's own session and user. Route signatures, response models and the OpenAPI schema are unchanged, so the generated frontend client is unaffected. No models, migrations or other modules are touched, and nothing else imports from `items.py`. The existing tests (`test_{read,update,delete}_item_not_found` and `..._not_enough_permissions`) already check every status code and message on these paths. One non-production problem: the new `def` line is 91 characters, so `ruff format --check` (in `scripts/lint.sh` and the pre-commit hook) fails on this file and CI lint will be red until it is reformatted.

## Questions for the author (ranked)

1. CI lint will fail: `ruff format --check` wants the `get_owned_item` signature wrapped over several lines. Can you run `scripts/format.sh` and push?
2. Was it on purpose that `get_owned_item` is a plain helper and not a FastAPI dependency? Its parameters are typed `SessionDep`/`CurrentUser`. If someone later wires it in with `Depends(get_owned_item)`, it becomes a path/dependency parameter and its behaviour and schema change. Plain `Session`/`User` types (or a comment) would make the intent clear.
3. Do any other routes (for example a future item sub-resource) need this check? If they do, should they use this helper now, so the rule lives in only one place?
4. Do you want to name the parameter `item_id` instead of `id`, which shadows the builtin? This would only be in the helper. The route parameter must stay `id` to keep the URL/OpenAPI contract.

VERDICT: safe-to-merge
